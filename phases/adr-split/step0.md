# Step 0: adr-extract

`docs/ADR.md`(1,431줄 / 122KB / ADR 67개)를 **ADR 1개당 파일 1개**로 분할하는 phase 의 첫 step. 본 step 은 `docs/adr/` 디렉터리를 만들고 원본의 67개 ADR 블록(001~067)을 **무손실로** 개별 파일로 추출한다. `docs/ADR.md`(인덱스 재작성)와 ADR-068 신규 작성은 다음 step 이다.

**핵심 제약**: 이 phase 는 **docs-only** 다. 저장소 전역에서 `docs/ADR.md#adr-032` 같은 **앵커 링크 참조가 0건**이고 모든 참조가 `ADR-044` 같은 순수 번호 텍스트라, 분할해도 깨지는 링크가 없다. 코드(`src/`·`app/`)는 전혀 건드리지 않는다.

## 읽어야 할 파일

먼저 아래를 읽고 설계 의도를 파악하라:

- `docs/plans/adr-split-per-file.md` — **이 phase 전체의 설계 스펙(단일 출처)**. 특히 §파일 규약 §1(파일명 `NNN-<slug>.md`)·§2(개별 파일 본문 템플릿), 그리고 **부록 표(68행, 번호→제목→상태→제안 슬러그)**. 슬러그·상태의 **정본은 이 부록 표**다.
- `docs/ADR.md` — **추출 원본**. 헤더 + `## 철학`(5줄) 다음 `### ADR-001` 부터 파일 끝까지가 ADR 본문 영역. 물리 순서는 뒤섞여 있다(040/036/033/031/042 등이 뒤에 삽입). 번호 기준으로 추출하면 자동 정규화된다.
- `CLAUDE.md`(루트) — 아키텍처 규칙·개발 프로세스 가드레일.

## 작업

### 1. `docs/adr/` 생성 + 67개 파일 추출 (일회성 스크립트 사용)

**추출 수단은 일회성 파싱 스크립트**다(사용자 확정). 스크립트는 **scratchpad 디렉터리에 작성해 실행**하고, 검증 통과 후 **삭제**한다. `scripts/` 아래에 두거나 커밋하지 않는다.

스크립트 알고리즘(Node `.mjs` 권장, UTF-8):

1. `docs/ADR.md` 를 읽는다.
2. `^### ADR-(\d{3}): (.+)$` 로 시작하는 줄을 ADR 헤더로 인식. 각 블록의 **본문**은 헤더 **다음 줄**부터 **다음 `### ADR-` 헤더 직전**(마지막 ADR 은 EOF)까지.
3. 블록 사이의 `---` 구분선: 각 ADR 본문 끝에 붙는 `---` 구분선과 그 주변 빈 줄은 **개별 파일에서 제거**한다(파일마다 매달린 `---` 이 남지 않도록). 무손실 검증(아래)은 본문들을 `---` 로 다시 이어 붙여 원본과 대조한다.
4. 각 번호 NNN(3자리 zero-pad)에 대해 `docs/adr/NNN-<slug>.md` 를 쓴다. `<slug>` 는 **부록 표의 제안 슬러그 맵을 스크립트에 내장**해 사용(67개). 파일 내용은 §2 템플릿:

   ```markdown
   [← ADR 인덱스](../ADR.md)

   # ADR-NNN: <원본 제목 그대로>

   > **상태**: <상태>

   <원본 본문 verbatim — 한 글자도 바꾸지 않음>
   ```

   - 헤딩은 `### ` → `# ` 로만 승격. 제목 텍스트는 원본 그대로.
   - **상태 줄 규칙**: 원본 본문에 이미 `**상태`(예: ADR-058 의 `**상태:** 채택 (2026-05-02)`) 로 시작하는 줄이 있으면 **`> **상태**:` 줄을 새로 넣지 않는다**(중복 금지) — 본문의 기존 줄이 상태를 대신한다. 없으면 부록 표 상태 열 값으로 `> **상태**: <상태>` 를 넣는다(028→`Superseded by ADR-032`, 043→`Superseded by ADR-044`, 062→`부분 supersede (ADR-067)`, 그 외 `Active`).
   - **여기서 상태를 새로 판정하지 마라.** 부록 표/기존 마커에 있는 것만 반영한다.

### 2. ADR-058 처리 (기계적 이동 + 보고만)

ADR-058(PersonaCard 전용 토큰)은 페르소나 제거(ADR-067)로 **실질 폐기 상태이나 본문에 supersede 마커가 없다**. 규칙대로 기존 `**상태:** 채택` 줄을 그대로 두고 **마커를 신설하지 마라**(범위 확대 지양). 이 사실은 index.json summary 에 **보고만** 한다.

### 3. 무손실 검증 후 스크립트 삭제

- **bijection**: 001~067 각 번호마다 `docs/adr/NNN-*.md` 정확히 1개. 총 67개.
- **무손실(bytes)**: 추출된 67개 파일에서 백링크·헤딩 줄·(추가한)상태 줄을 제외한 **본문**을 번호순으로 `---` 구분선과 함께 concat 한 결과가, 원본 `docs/ADR.md` 의 `### ADR-` 영역에서 헤딩 줄을 같은 방식으로 처리한 것과 **바이트 동등**임을 확인. 기준 원본은 `git show HEAD:docs/ADR.md` 로 확보(작업 트리 변경과 무관하게 원본 스냅샷).
- 검증이 통과하면 scratchpad 의 스크립트를 삭제한다.

### 4. `docs/ADR.md` 는 이 step 에서 손대지 않는다

원본 `docs/ADR.md` 는 그대로 둔다. 인덱스 재작성은 step 1 이며, step 1 의 무손실 대조 기준으로도 필요하다.

## 검증 절차

1. 위 AC 커맨드를 실행한다(bijection 출력 없음 = 정상).
2. 무손실 검증(§3): 추출 본문 concat == 원본 ADR 영역(헤딩 승격·백링크·상태 줄만 허용 diff).
3. scratchpad 스크립트가 삭제되어 `scripts/`·저장소에 남지 않았는지 확인.
4. 아키텍처 체크리스트:
   - ARCHITECTURE.md 디렉터리 규칙 위반 없음(문서 추가만).
   - CLAUDE.md CRITICAL 규칙 위반 없음(코드·데이터 무변경).
5. `phases/adr-split/index.json` step 0 → `completed`, summary 에 "docs/adr/ 67개 추출(무손실 검증 통과), ADR-058 마커 미신설 보고, 스크립트 삭제, green" 기록.

## 금지사항

- 추출 스크립트를 `scripts/` 아래에 두거나 커밋하지 마라. 이유: 일회성 도구이며, 영구 스크립트는 CLAUDE.md "새 스크립트 = 테스트 동반" 규칙을 유발해 범위를 넓힌다. scratchpad 에서 실행 후 삭제.
- ADR 본문 텍스트를 한 글자도 바꾸지 마라(오타 수정·문구 개선·재포맷 포함). 이유: 무손실 이동이 이 step 의 성공 기준. 허용 diff 는 헤딩 레벨(h3→h1)·백링크 줄·상태 줄뿐.
- 새 supersede 관계를 임의로 판정하지 마라. 이유: 부록 표/기존 마커에 있는 것만 반영. ADR-058 은 마커 없음 → 기존 줄 유지 + summary 보고.
- `docs/ADR.md` 를 이 step 에서 수정하지 마라. 이유: 인덱스 재작성은 step 1 이고, 원본은 step 1 무손실 대조 기준(`git show HEAD:docs/ADR.md`)으로 필요.
- 코드(`src/`·`app/`)·데이터(`data/`)를 변경하지 마라. 이유: 본 phase 는 docs-only.
- 기존 테스트를 깨뜨리지 마라.
