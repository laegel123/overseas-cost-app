# Step 1: adr-068-and-index

`adr-split` phase 의 두 번째 step. step 0 이 만든 `docs/adr/001~067-*.md`(67개) 위에서, (1) 본 분할 결정을 기록하는 **ADR-068 신규 파일**을 작성하고, (2) `docs/ADR.md` 를 **68행 인덱스**로 재작성한다.

## 읽어야 할 파일

- `docs/plans/adr-split-per-file.md` — 설계 스펙(단일 출처). 특히 §파일 규약 §2(본문 템플릿)·§3(`docs/ADR.md` 인덱스 새 구성)·§실행 순서 2·3, 그리고 **부록 표(68행)**. 인덱스의 제목·상태·슬러그 **정본은 부록 표**.
- `docs/ADR.md` — **아직 원본(전체 본문)** 상태다(step 0 은 이 파일을 안 건드렸다). 여기서 `# Architecture Decision Records` 헤더와 `## 철학`(5줄)을 **그대로 보존**해 인덱스에 재사용하고, 각 ADR 의 **결정** 줄에서 인덱스 요약을 도출한다.
- `docs/adr/`(step 0 산출 67개 파일) — 인덱스 행·요약의 원천(부록 표와 교차 확인).
- `CLAUDE.md`(루트) — 문서 색인·개발 프로세스 규칙.

## 작업

### 1. ADR-068 신규 작성 — `docs/adr/068-adr-doc-split.md`

§2 템플릿으로 본 분할 결정 자체를 새 구조 안에 기록한다(self-consistent). 담을 내용:

- **맥락**: `docs/ADR.md` 단일 파일 비대화(1,431줄), 앵커 링크 참조 0건(전부 번호 텍스트 참조) → 분할해도 무손실.
- **결정**: 인덱스(`docs/ADR.md`) + ADR 1개당 파일 1개(`docs/adr/NNN-<slug>.md`). 번호가 곧 주소, `NNN-` 3자리 zero-pad 로 사전순=번호순. 새 결정 = 새 파일 + 인덱스 1행.
- **대안 검토(기각)**: (A 채택) 파일당 1 ADR + 인덱스. (B) 테마별 그룹 파일 — 한 ADR 이 여러 테마 걸침·경계 모호로 기각. (C) 번호 구간 분할(001-020 등) — 임의 경계·머지 충돌 잔존으로 기각. (D) 번호만 파일명(`044.md`) — 브라우징성 저하로 기각(슬러그는 장식용, 개명 무해).
- **결과/영향**: 기존 참조 전부 유효(인덱스 착지 + 번호 텍스트 불변). 새 ADR = 새 파일 → 머지 충돌·거대 diff 소멸. 인덱스 표는 수동 유지(자동 생성 스크립트는 범위 밖).

상태 줄: `> **상태**: Active`(신규). 헤딩: `# ADR-068: ADR 문서 구조 = 인덱스 + 파일당 1 ADR 로 분할`.

### 2. `docs/ADR.md` 를 인덱스로 재작성

§3 구성을 따른다:

- `# Architecture Decision Records` 헤더 유지.
- 안내 문단: "각 결정은 `docs/adr/NNN-<slug>.md` 파일 1개로 관리하며 본 문서는 전체 인덱스" + 새 결정 워크플로우(다음 번호로 새 파일 + 인덱스 1행 추가) + supersede 표기 규칙(새 ADR 본문 "Supersedes ADR-X", 뒤집힌 ADR 상태 줄 "Superseded by ADR-N").
- `## 철학` — **기존 5줄 그대로**(문구 개선·재작성 금지).
- `## 인덱스` — **68행 표**: `| [NNN](adr/NNN-<slug>.md) | 제목 | 상태 | 요약 |`.
  - 링크·제목·슬러그·상태: **부록 표 정본** 사용(068 행 포함).
  - **상태 열**: 부록 표 상태 열을 사용(028→`Superseded by ADR-032`, 043→`Superseded by ADR-044`, 062→`부분 supersede (ADR-067)`, 032/044/067 은 supersede**하는** 쪽이라 `Active`, 그 외 `Active`). 새 판정 금지.
  - **요약 열**: 각 ADR 의 **결정** 줄을 1줄(≤40자 목표)로 압축. 본문에서 도출하되 본문을 복제하지 마라.
- **기존 ADR 본문은 전부 제거**한다(파일로 이동됨). 인덱스에 `### ADR-` 헤딩·결정/맥락/트레이드오프 본문이 남으면 안 된다.

### 3. step 0 산출물은 재생성하지 않는다

`docs/adr/001~067-*.md` 는 step 0 에서 무손실 검증 완료. 본 step 에서 **068 만 신규 작성**하고 001~067 파일은 수정하지 마라.

## Acceptance Criteria

```bash
ls docs/adr | wc -l                       # 68 (67 + 068)
ls docs/adr/068-*.md                       # 존재
test "$(grep -c '^### ADR-' docs/ADR.md)" = "0" && echo "no-body-OK"   # 인덱스에 ADR 본문 헤딩 잔존 0
grep -Eoc '\]\(adr/0[0-9][0-9]-' docs/ADR.md   # 68 (인덱스 링크 68행)
npm run typecheck && npm run lint && npm test  # 코드 무변경 → 그린 유지
```

## 검증 절차

1. 위 AC 통과: 파일 68개, 068 존재, `docs/ADR.md` 에 ADR 본문 헤딩 0, 인덱스 링크 68행.
2. 인덱스 표의 모든 `adr/NNN-*.md` 링크가 실재 파일로 해석되는지 확인(68행 ↔ 68파일 1:1).
3. `## 철학` 5줄이 원본과 동일한지 확인(개선·재작성 없음).
4. 단일 출처: 어떤 ADR 본문도 인덱스와 파일에 **중복 존재하지 않음**(인덱스는 링크·제목·상태·요약만).
5. `phases/adr-split/index.json` step 1 → `completed`, summary 에 "ADR-068 신규 + docs/ADR.md 68행 인덱스 재작성(본문 전량 파일 이동), green" 기록.

## 금지사항

- 인덱스 표에 ADR 본문(결정/맥락/트레이드오프)을 복제하지 마라. 이유: 단일 출처 규칙 — 본문은 파일에만, 인덱스는 링크·제목·상태·요약만.
- step 0 이 만든 001~067 파일을 재생성·수정하지 마라(068 만 신규). 이유: 무손실 이동은 step 0 에서 검증 완료 — 재작업은 회귀 위험.
- `## 철학` 문구를 개선·재작성하지 마라. 이유: 정밀 수정 원칙 — 기존 그대로 보존.
- 새 supersede 관계를 임의 판정하지 마라. 이유: 부록 표 상태만 사용.
- 코드(`src/`·`app/`)를 변경하지 마라. 기존 테스트를 깨뜨리지 마라.
