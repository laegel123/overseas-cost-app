# ADR-068: ADR 문서 구조 = 인덱스 + 파일당 1 ADR 로 분할

> **상태**: Active

**맥락:**

`docs/ADR.md` 가 1,431줄 / 122KB / ADR 67개로 커졌다. 단일 파일이라 (1) 특정 ADR 로의 이동이 스크롤·검색에 의존하고, (2) 새 ADR 추가 시 diff·머지 충돌 표면이 파일 전체이며, (3) 앞으로도 무한히 커진다.

**핵심 사실**: 저장소 전역에서 `docs/ADR.md#adr-032` 같은 **앵커 링크 참조가 0건**이다. 모든 참조는 `ADR-044`, `Superseded by ADR-032`, `docs/ADR.md ADR-066` 같은 **순수 텍스트(번호) 참조**뿐이다. 따라서 번호→파일 매핑만 결정론적이면 이동은 오히려 쉬워지고, 기존 참조는 전부 유효하게 유지된다.

**결정:**

1. `docs/ADR.md` 는 **인덱스**로 존치: 헤더 + 철학 + 워크플로우 안내 + 68행 인덱스 표.
2. 각 ADR 본문은 `docs/adr/NNN-<slug>.md` 파일 1개로 관리.
3. **번호가 곧 주소**: `ADR-044` → `docs/adr/044-*.md`. 파일명 `NNN-` 접두는 3자리 zero-pad 라 사전순 = 번호순.
4. **새 ADR = 새 파일 + 인덱스 1행 추가**: 기존 파일 무변경 → 머지 충돌·거대 diff 소멸.
5. supersede 표기: 새 ADR 본문에 "Supersedes ADR-X", 뒤집힌 ADR 상태 줄에 "Superseded by ADR-N".

**대안 검토:**

- **(A) 채택 — 파일당 1 ADR + 인덱스**: 번호가 주소, 새 ADR = 새 파일, 머지 충돌 소멸, 인덱스 표로 전체 훑기 유지.
- **(B) 기각 — 테마별 그룹 파일**: 한 ADR 이 여러 테마에 걸치고 경계가 모호. 어느 파일에 추가할지 판단 필요.
- **(C) 기각 — 번호 구간 분할 (001-020.md 등)**: 임의 경계, 구간 파일 내 머지 충돌 잔존.
- **(D) 기각 — 번호만 파일명 (044.md)**: 100% 기계적이지만 `ls docs/adr/` 브라우징성 저하. 슬러그가 값싸고 링크 가독성 ↑.

**결과 / 영향:**

- CLAUDE.md·README·ARCHITECTURE 등의 기존 `docs/ADR.md` 참조가 그대로 인덱스로 착지 → 깨지는 링크 없음.
- `ADR-NNN` 텍스트 참조는 번호 불변이라 전부 유효.
- 새 ADR 추가 시 1 파일 생성 + 인덱스 1행 → 커밋 diff 최소화.
- 인덱스 표는 수동 유지 (자동 생성 스크립트는 별도 phase 로 분리).
- supersede 관계는 번호 교차참조라 파일 분리와 무관하게 유지.

**관련:** `docs/plans/adr-split-per-file.md` (설계 스펙), `docs/ADR.md` (인덱스), `docs/adr/*.md` (개별 결정).
