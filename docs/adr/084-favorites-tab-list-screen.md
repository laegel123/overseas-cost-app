# ADR-084: 즐겨찾기 탭 — 라우팅 단축 대신 목록 화면 (ADR-041 부분 대체)

**상태:** 채택 (2026-11-26)

**맥락:**

ADR-041 은 v1.0 에서 즐겨찾기 탭을 "첫 번째 즐겨찾기 도시의 Compare 로 redirect" 하는 단축으로 두었다.
실사용에서 세 가지가 걸렸다.

- 즐겨찾기가 여러 개여도 탭으로는 첫 도시만 열린다.
- 탭 이름은 "즐겨찾기"인데 비교 화면이 나와 "비교" 탭과 동작이 겹친다.
- 즐겨찾기가 없으면 Alert 를 띄우고 홈으로 튕긴다.

**결정:**

- 즐겨찾기 탭은 일반 탭 화면 `app/(tabs)/favorites.tsx` 다. `_layout` 의 `tabPress` redirect 를 제거한다.
- 목록은 즐겨찾기 스토어 순서 그대로, 홈 "최근 본 도시"와 같은 `RecentRow` 를 재사용한다. 행 탭 → `/compare/{cityId}`.
- 0개일 때는 화면 안에서 안내 문구 + "도시 둘러보기" CTA(홈으로 이동)를 보여준다. Alert 는 쓰지 않는다.
- 광고는 넣지 않는다 (ADR-077: 홈·비교·상세의 ready 상태만).
- 목록에서의 해제·정렬·편집은 넣지 않는다. 해제는 Compare 화면의 ⭐ 에서만 한다.
- 비교 탭의 단축(ADR-041)은 그대로 둔다.

**대안:**

- **단축 유지** — 위 세 문제가 남는다. 기각.
- **`FavCard` 그리드** — 가로 스크롤용 카드라 세로 목록에 맞추려면 변형이 필요하다. 기존 행 재사용이 더 단순하다. 기각.
- **목록에서 바로 해제** — 실수 해제 대비(되돌리기)가 필요해 범위가 커진다. 필요해지면 별도 결정.

**결과:**

- ADR-041 중 즐겨찾기 탭 부분을 대체한다. 비교 탭 부분은 유효하다.
- 화면이 도시·환율 로드(loading/error/ready)를 홈과 같은 방식으로 직접 수행한다. 두 화면의 로드 코드가 중복된다 — 세 번째 사용처가 생기면 hook 으로 추출한다.
- Maestro: `tabs-empty-alert` 에서 즐겨찾기 탭 구간을 뺐고 `favorites-tab-list` 를 추가했다.
