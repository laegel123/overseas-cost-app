# ADR-089: 비교 탭 = 두 도시 선택 화면, 기준 도시는 `?base=` (ADR-041 비교 탭 부분 supersede)

**상태:** 채택 (2026-11-27)

**맥락:**

두 가지가 겹쳐 있었다.

- **비교 탭이 중복이다.** ADR-041 은 비교 탭을 자체 화면 없이 `recent[0] ?? favorites[0]` 의
  `/compare/<id>` 로 redirect 하는 단축으로 두었다. 홈의 "최근 본 도시" 목록과 즐겨찾기
  탭(ADR-084)이 이미 같은 곳으로 한 번에 데려가므로 탭 한 칸이 같은 일을 세 번째로 한다.
  도시가 하나도 없으면 홈으로 튕기고 `Alert` 를 띄우는 것도 탭 동작으로는 거칠다.
- **서울 vs X 만 볼 수 있다.** 후보지를 두세 곳으로 좁힌 사용자가 정말 궁금한 것은
  "밴쿠버와 토론토 중 어디가 더 드나"인데, 지금은 두 화면을 오가며 머릿속으로 빼야 한다.

중복인 탭 자리에 "도시끼리 비교" 를 넣으면 둘이 한 번에 풀린다.

**결정:**

1. **비교 탭은 두 도시를 고르는 일반 탭 화면이다** (`app/(tabs)/compare.tsx`).
   `_layout` 의 `tabPress` redirect(와 그에 딸린 `Alert`·`useRouter`·recent/favorites 참조)를
   제거한다. 왼쪽 칸 = 기준 도시, 오른쪽 칸 = 대상 도시이고, 칸을 누르면 21개 도시
   전부(서울 포함)가 한글 가나다순으로 뜬다. 반대편 칸에 든 도시는 비활성이다.
   값은 고를 때마다 `useComparePairStore` (`comparePair:v1`) 에 저장한다.
   저장된 id 가 현재 도시 목록에 없으면 그 칸은 빈 칸으로 취급한다 (store 값은 지우지 않는다).
2. **기준 도시는 query param `?base=<id>` 다.** `/compare/[cityId]?base=<id>`,
   `/detail/[cityId]/[category]?base=<id>`. 생략하거나 `seoul` 이면 지금까지의 서울 모드와
   완전히 동일하게 동작한다 — 기존 링크·테스트·Maestro flow 가 그대로 유효하다.
3. **서울은 항상 왼쪽(기준)이다.** 어느 칸에 서울을 넣었든 선택 화면은
   `/compare/<서울이 아닌 도시>` (`?base` 없음)로 이동한다. 서울은 학비·세금·비자가 정책상
   0원이라 대상(오른쪽)에 두면 `0 ÷ 값` 배수가 되어 `formatMultiplier`·`isHot` 이 throw 한다
   (`src/lib/format.ts`). 공용 lib 을 고치는 대신 그 조합 자체를 만들지 않는다.
   칸에 보이는 순서는 사용자가 고른 그대로 둔다.
4. **선택 화면에는 광고를 넣지 않는다.** ADR-077 의 "홈·비교·상세 ready 의 footer" 중
   "비교"는 `app/compare/[cityId].tsx` 를 뜻한다. 선택 화면은 대상이 아니다.
   (즐겨찾기 탭과 같은 판단 — ADR-084.)
5. **카테고리 포함 토글 저장 키는 도시끼리 모드에서 `"<base>|<cityId>"`** 다. 서울 모드는
   현행대로 `cityId`. `useCategoryInclusionStore` 는 문자열 키 map 이라 store 변경 없이 된다.
   도시끼리 화면에서 학비를 켜도 서울 기준 화면이 바뀌지 않게 하려는 분리다.
   기본값(rent/food/transport ON, tuition/tax/visa OFF — ADR-067)은 그대로.
6. 탭 라벨·아이콘("비교")은 바꾸지 않는다. 좌우 바꾸기 버튼·최근 비교 쌍 목록·검색창은
   넣지 않는다 (도시가 21개뿐이다).

**대안:**

- **경로 세그먼트 변경 (`/compare/[baseId]/[cityId]`)** — 기준 도시가 주소에 드러나 읽기는
  좋지만 기존 링크·테스트·flow 를 전부 고쳐야 하고 얻는 것이 없다. 기각.
- **도시끼리 전용 화면 신설** — 기존 화면은 손대지 않아 안전하지만 비교(475줄)·상세(662줄)의
  계산·표시 코드를 복제하게 되고 이후 수정이 두 벌이 된다. 두 화면의 계산은 이미 "두 도시를
  같은 함수에 통과"시키는 구조라(`COMPARE_CATEGORIES[].getValue`, `buildSections`) 왼쪽을
  `seoul` 고정에서 변수로 바꾸는 쪽이 훨씬 작다. 기각.
- **비교 탭 = 도시 순위 화면** (전체 도시를 비싼 순으로) — 중복은 풀리지만 "두 후보 중 어디"
  라는 실제 질문에 답하지 않는다. 기각.
- **탭을 3개로 줄이기** (비교 탭 제거) — 중복만 없애고 새 가치가 없다. 디자인의 4탭 구성도
  깨진다. 기각.
- **탭이 곧 비교 화면** (마지막 쌍을 바로 렌더) — 첫 진입에 보여줄 것이 없고, 쌍을 바꾸려면
  결국 선택 UI 가 필요하다. 기각 (사용자 확정).

**결과:**

- **`docs/PRD.md` 의 비교 탭 서술과 달라진다.** PRD 는 수정 금지(단일 출처)이므로 여기에
  기록한다 — PRD 가 말하는 "비교 탭 = 마지막으로 본 비교 도시로 이동"은 ADR-041 의 단축
  이고, 본 ADR 이 그 자리를 두 도시 선택 화면으로 바꾼다. 서울 vs X 진입 흐름(홈·즐겨찾기·
  온보딩)은 PRD 그대로 유지된다.
- ADR-041 은 즐겨찾기 탭 부분이 ADR-084 로, 비교 탭 부분이 본 ADR 로 대체되어 전체가
  superseded 가 된다.
- 도시끼리 모드에서는 즐겨찾기 별(어느 도시의 별인지 모호)을 숨기고 `pushRecent` 를
  호출하지 않는다. 홈의 최근 목록은 계속 서울 모드로 열린다.
- **세금은 현행 유지.** 21개 도시 모두 `tax` 데이터가 비어 있고 그 상태에서는 직접 입력도
  동작하지 않는다 (`resolveTaxChoice` 가 entries 없으면 null). 따라서 세금 카드는 비교
  화면에서 숨겨지고 상세는 빈 상태를 보여준다. `resolveTaxChoice`·`TaxChoiceSheet` 는
  고치지 않고, 데이터가 생겼을 때 학비와 같은 구조로 동작하도록 코드 경로만 공유한다.
  세금 데이터 채우기는 별도 작업이다.
- 서울이 아닌 도시가 한쪽만 결측이면 그 값은 `—` 로 표시하고 배수를 내지 않으며 hero
  합계에서 뺀다. 현재 데이터로는 발생하지 않는 조합이라 Jest fixture 로만 검증한다.
- Maestro: 비교 탭 redirect 를 검증하던 flow 2개를 고치고 도시끼리 flow 를 추가한다.
